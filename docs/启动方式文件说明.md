# 各启动方式专用文件说明

官方 Swiss 发布包按 JB / ODE 方式分目录提供不同的引导文件。本仓库同样按设备分目录，
**所有目录里装的是同一份汉化固件**（`firmware/swiss.dol`，自解压 packed DOL），
区别只是包装格式，方便不同设备按自己能识别的方式加载。

> ⚠️ **禁止商业使用 / NON-COMMERCIAL USE ONLY**（本仓库原创内容）。
> 上游 Swiss / GNU Unifont 的 GPL-2.0 材料不受此限制，仍按 GPL-2.0 授权；
> 详见根目录 `LICENSE`、`NOTICE.md`、`LICENSE-GPL-2.0.txt`。

## 总览

| 目录 | 适用设备 / 方式 | 放哪里 |
|---|---|---|
| `firmware/` | SD 卡 `IPL.dol`、PicoBoot / CubiBoot | SD 卡根目录，改名 `IPL.dol` |
| `igr/` | 游戏内复位（所有方式通用） | `SD:\swiss\patches\apploader.img` |
| `gcloader/` | GCLoader | SD 卡根目录，保持 `boot.iso` |
| `iso/` | 刻盘 / 其它 ODE | 按设备要求 |
| **`ActionReplay/`** | Action Replay + SD 卡适配器 | SD 卡根目录，两个文件 |
| **`FlippyDrive/`** | FlippyDrive ODE | 解压 zip 到 SD 卡根目录 |
| **`WiikeyFusion/`** | Wiikey Fusion / WASP Fusion | SD 卡根目录（`.fzn` / `.fzn.fw`） |
| **`Wii/`** | Wii（Homebrew Channel） | 解压 zip 到 Wii 的 SD 卡根目录 |
| **`WODE/`** | Wii Optical Drive Emulator | 按 WODE 的 extcfg 流程加载 ISO |
| **`MemoryCard/`** | 记忆卡存档漏洞 / GCMM 等 | 用存档管理工具写入 GC 记忆卡 |

`IPL.dol`、`apploader.img` 与这些新文件出自同一次构建，**换固件时要一起换**。
`firmware/swiss-wiiload.dol` 是原始 DOL，只用于 wiiload 网络推送，**不要**放进 SD 卡。

> r8（字库扩到 8887 字）重编了固件，因此本页所有设备目录、ISO、`SDLOADER.BIN`、
> `reboot.dol`、GCI 都已换成 r8 版本，与 r7 的同类文件**不能混用**。
> 各文件当前 SHA-256 见根目录 `SHA256SUMS.txt`。

## Action Replay

`ActionReplay/` 下两个文件都放到按 Action Replay 要求格式化好的 SD 卡根目录：

| 文件 | 说明 |
|---|---|
| `AUTOEXEC.DOL` | 就是 `firmware/swiss.dol` 改名，Swiss 本体 |
| `SDLOADER.BIN` | 替换 Action Replay 原来的 `SDLOADER.BIN`，负责直接引导 Swiss |

两个文件缺一不可，且必须同版本。`SDLOADER.BIN` 不是通用加载器，它内嵌了本次构建的
压缩镜像，`build_boot_variants.py` 会校验它与主固件同源。

## FlippyDrive

把 `FlippyDrive/EXTRACT_TO_ROOT.zip` 解压到 FlippyDrive 使用的 SD 卡根目录，
得到 `boot.dol`（同样是主固件改名）。**保持文件名 `boot.dol`**，
不要放进子目录或改名。开机由 FlippyDrive 自动引导。

## Wiikey Fusion / WASP Fusion

| 文件 | 用途 |
|---|---|
| `swiss-zh.fzn` | 从 WKF/WASP 的 SD 槽更新 Swiss 菜单用的固件镜像（`GSWAGL`，补齐到 1856 KiB） |
| `swiss-zh.fzn.fw` | 仅用于把 WKF/WASP 恢复回 v1.0 autoboot 固件；**必须与 `.fzn` 配合、且只能从 SDGecko 槽执行** |
| `RecoveryISO/swiss-zh_Recovery.iso` | 恢复模式盘（`GBLPGL`），替代原厂 1.2 recovery，用于在恢复模式下重新刷写 |

⚠️ `.fzn` / `.fzn.fw` 是**固件刷写文件**，只适用于 Wiikey Fusion / WASP Fusion，
刷错设备或中断可能变砖。若设备要求固定文件名，请按设备说明把 `swiss-zh.fzn`
改成它认的名字（官方发布包使用带版本号的 `swiss_rXXXX.fzn`，说明文件名本身可自定义）。
Recovery ISO 前 32 KiB 是上游 `recovery_bootloader.iso` 的引导头，盘体是 PAL 版 Swiss ISO。

## Wii

把 `Wii/EXTRACT_TO_ROOT.zip` 解压到 **Wii 的 SD 卡根目录**，得到：

```
apps/swiss-gc/boot.dol        ← Wii 模式启动器，内嵌本次汉化 Swiss 的 reboot.dol
apps/swiss-gc/LICENSE.txt     ← GPL-2.0 全文
apps/swiss-gc/NOTICE.md       ← 本仓库原创内容的非商业许可说明
apps/swiss-gc/licenses/       ← 上游第三方依赖许可文本
```

从 Homebrew Channel 启动 `swiss-gc`，启动器会切换主机到 GameCube 模式并跳转执行内嵌的
汉化 Swiss。`boot.dol` 本体是从本仓库基线源码用 libogc2 `wii_rules` 编译的，
已与上游 `dol2ipl.py` 的输出逐字节比对；它本身没有需要汉化的界面文字。

## WODE

`WODE/swiss-zh(wode_extcfg).iso` 是用 `eltorito-wode.hdr`（Game ID `GWDPCF`）生成的
可引导 ISO，按 WODE 的 extcfg 流程加载。

## MemoryCard

| 文件 | 内部文件名 | 说明 |
|---|---|---|
| `boot.gci` | `boot.dol` | 给以 `boot.dol` 为入口的存档漏洞 / 加载器 |
| `xeno.gci` | `xeno.dol` | 给 Xeno / 对应 exploit 使用的入口 |

用 GCMM 等记忆卡管理工具写入 GameCube 记忆卡，再由对应的存档漏洞启动。
GCI 由 `tools/build_boot_variants.py` 纯 Python 组装，与上游 `dol2gci.exe`
的输出逐字节一致。

## 验证状态与重新生成

全部产物由 `tools/build_boot_variants.py` 一次生成并自检（26 项检查），
Wii 的 DOL 段注入、GCI 组装另有上游工具的逐字节对照；ISO 类共用
`tools/build_gcloader_iso.py` 的 20 项 El Torito 自检。

```bash
python tools/build_boot_variants.py                # 生成全部并自检
python tools/build_boot_variants.py --verify-only  # 只校验，不改动文件
python tools/build_gcloader_iso.py --all --reference <官方 boot.iso>
```

⚠️ 这些设备（Action Replay、FlippyDrive、Wiikey Fusion、Wii、WODE、记忆卡）
**在本次开发环境中都没有真机实测**：本机是 PicoLoader / CubiBoot + SD 卡启动。
文件结构与上游 r2119 发布包逐项对齐、二进制已做同源自检，但仍需各设备用户实机确认。
请在论坛帖或 Issue 反馈结果；若某个格式确有问题，按不可变发布规则发下一个版本，
不要修改已发布 Release。

ISO9660 会写入生成时刻的时间戳，所以同一份 DOL 重复生成 SHA-256 不同属正常现象，
以发布包 `SHA256SUMS.txt` 为准。构建资产来源见 `tools/boot/README.md`。
