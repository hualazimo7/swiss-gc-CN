# GCLoader 用 `boot.iso` 说明

## 为什么需要 ISO

GCLoader（以及其它光驱替代 ODE）把 SD 卡上的镜像当作**一张真实的 GameCube 光盘**挂给主机。
主机上电后仍然走原厂 IPL 的启动流程：读光盘头 → 加载 apploader → 由 apploader 加载 DOL。
它不像 PicoBoot / CubiBoot 那样能直接从文件系统里选一个 `.dol` 执行，所以只给 DOL 不够，
必须给一张**可引导的光盘镜像**。原版 Swiss 的发布包里同样带 `GCLoader/boot.iso`
（放在 `EXTRACT_TO_ROOT.zip` 中），本包提供的是汉化版的对应产物。

## 用法（GCLoader）

1. 准备 GCLoader 自己那张 SD 卡，按 GCLoader 固件支持的文件系统格式化（通常用 FAT32）。
2. 把本目录的 **`boot.iso` 复制到 SD 卡根目录**，文件名必须保持 `boot.iso`（全小写）。
   GCLoader 只认根目录下这个固定名字，放进子目录或改名都会开机直接进原厂菜单/黑屏。
3. 同一张卡上照常放好 `swiss/` 目录与游戏镜像。若要用游戏内复位，路径必须是
   `SD:\swiss\patches\apploader.img`（见 `igr/` 里的离线包）。
4. 插卡开机，GCLoader 会自动引导进 Swiss 简体中文版。

> 升级提醒：`boot.iso` 里装的就是 `firmware/swiss.dol`（同一次构建的 packed 自解压 DOL）。
> 换固件时请一并换 ISO 和 `apploader.img`，不要新旧混用。

## 区域 ISO（`iso/` 目录）

| 文件 | Game ID | 用途 |
|---|---|---|
| `gcloader/boot.iso` | `GSWAGL` | **GCLoader 专用**，全区，放 SD 卡根目录命名 `boot.iso` |
| `iso/swiss-zh(ntsc-u).iso` | `GSWEGL` | 刻录 miniDVD / 其它 ODE，NTSC-U 主机 |
| `iso/swiss-zh(ntsc-j).iso` | `GSWWGL` | 同上，NTSC-J 主机 |
| `iso/swiss-zh(pal).iso` | `GSWPGL` | 同上，PAL 主机 |

GCLoader 不需要按区域挑镜像，直接用 `boot.iso`；官方给 GCLoader 的也是全区 ID。

## 镜像是怎么做出来的

复刻上游 `Makefile` 的 `build` 目标（原命令用 `mkisofs`/`xorrisofs`）：

```
mkisofs -R -J -G eltorito-gcode.hdr -no-emul-boot -eltorito-platform PPC \
        -b swiss-zh.dol -o boot.iso swiss-zh.dol LICENSE.txt
```

- 32 KiB 的 `tools/iso/eltorito-gcode.hdr` 被 `-G` 原样写到镜像前 16 扇区，内含
  GameCube 光盘头（`GSWAGL`、magic `C2339F3D`）、`"El Torito" apploader` 与最小 FST；
  已核对与官方 r2119 `boot.iso` 的前 32768 字节**逐字节相同**。
- apploader 会解析 ISO9660 的 El Torito boot catalog，找到 default entry 指向的
  boot image LBA，把那里的内容当 DOL 校验并加载。因此 validation entry 的
  **platform ID 必须是 1（PowerPC）**，校验和也要有效。
- 老版本 Windows `mkisofs`（例如 VMware Workstation 自带的 2.01）不支持
  `-eltorito-platform PPC`，会写成 0（x86）。`tools/build_gcloader_iso.py`
  在生成后强制修正该字节并重算 16 位校验和，使输出与上游 Linux CI 的
  `xorrisofs` 产物等价。

自行生成 / 重新打包（换成你自己编译的 DOL）：

```bash
python tools/build_gcloader_iso.py --all
python tools/build_gcloader_iso.py --dol path/to/swiss.dol --out path/to/boot.iso
python tools/build_gcloader_iso.py --verify-only --all    # 只校验不重新生成
```

脚本会自动寻找 `xorrisofs` / `mkisofs`（含 VMware 自带的那个），跑完打印 20 项自检结果。
ISO9660 会写入生成时刻的时间戳，所以同一份 DOL 重复生成 SHA-256 不同属正常现象；
发布包里的 `SHA256SUMS.txt` 以当次实际发布的文件为准。

## 验证状态

- ✅ 20 项自检全部通过：光盘头、PVD、El Torito validation/default entry、
  platform ID 与校验和、boot image 内容与 DOL 全文一致、目录记录大小、
  以及 apploader 会对 DOL 头做的全部检查（段对齐、越界、入口点、BSS 地址）
- ✅ 与官方 `v0.6r2119` 的 `GCLoader/boot.iso` 结构对照一致：
  boot catalog 都在 LBA 32、DOL 都在 LBA 42、前 32 KiB 头完全相同
- ✅ Dolphin 的 `DolphinTool header` 能正确识别本镜像（Game ID `GSWAGL`、Country `World`）
- ⚠️ Dolphin 直接启动会黑屏，但**官方原版 `boot.iso` 在本机 Dolphin 上同样黑屏**，
  说明是 Dolphin 不支持这种 El Torito 自制盘的启动路径，与本镜像无关
- ⚠️ **GCLoader 真机尚未实测**：本次开发环境是 PicoLoader / CubiBoot + SD 卡启动。
  结构已与官方镜像对齐，但需要 GCLoader 用户实机确认一次；请在论坛帖或 Issue 里反馈结果
