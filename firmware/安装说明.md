# Swiss 简体中文版（上游 commit 62a8b9a2 / revision 2154）

GameCube 自制程序加载器 [Swiss](https://github.com/emukidid/swiss-gc) 的简体中文构建。
基于上游 **master commit 62a8b9a2**（2026-11-05，界面显示 revision 2154；比官方最新发布 v0.6r2119 新 35 个提交），界面文本、设置项、帮助说明、错误提示已全部中文化，
并支持在 SD 卡上直接使用中文文件名。

---

## 一、安装

包里有两个 DOL，**放 SD 卡的是 `swiss.dol`**，别用错：

| 文件 | 大小 | 用途 |
|---|---|---|
| **`swiss.dol`** | 约 1.1 MB | **自解压镜像**。SD 卡启动、CubiBoot / PicoBoot / WODE 用它；**GCLoader 请看方式 C，要把它打进 `boot.iso`** |
| `swiss-wiiload.dol` | 约 3.4 MB | 原始构建，**仅**用于 wiiload 推送到一台已在运行的 Swiss |

原因：原始构建链接在 `0x80003100`，这是 IPL 类加载器（CubiBoot、PicoBoot）自己占用的
地址区间；加载它会把加载器本身覆盖掉，表现就是**选完文件即黑屏**。官方发布版用的是
自解压格式——stub 放在加载器内存之上，运行时把真正的程序解压到 `0x80003100`。
本包的 `swiss.dol` 就是按同样方式打包的。

### 方式 A：SD 卡（CubiBoot / PicoBoot / 光驱替代设备）

1. 把 **`swiss.dol`** 复制到 SD 卡根目录
   - CubiBoot：在菜单里直接选它
   - PicoBoot：改名为 `ipl.dol`（这是 PicoBoot 的默认文件名，除非你改过）
2. SD 卡插入记忆卡槽 B（或你的适配器对应插槽）
3. 开机

**保留一个能用的备份**：升级前把旧的 DOL 改名留一份（例如 `swiss-old.dol`）。
若新版本黑屏，换回旧文件即可恢复。

### 方式 B：网络推送（已有一台能跑 Swiss 的机器 + 宽带网卡）

```bash
python tools/wiiload.py 192.168.1.2 swiss-wiiload.dol
```

⚠️ 推送请用 `swiss-wiiload.dol`。推送后 Swiss 会重启并运行新程序，SD 卡上的文件不受影响。
若推送中断，主机不会卡死（内部有 10 秒接收超时），重新推送即可。

### 方式 C：GCLoader / 光盘镜像（ISO）

GCLoader 等光驱替代设备把镜像当一张真实光盘来引导，**不能直接选 `.dol`**。
本包已备好现成镜像，不必自己做：

1. 把 **`gcloader/boot.iso`** 复制到 GCLoader 那张 SD 卡的**根目录**，
   文件名保持 `boot.iso` 不变（GCLoader 固件固定找这个名字）
2. 同一张卡上照常放 `swiss/` 目录（含 `patches/apploader.img`）和游戏镜像
3. 开机即自动进入中文 Swiss

`iso/` 目录另有 `ntsc-u` / `ntsc-j` / `pal` 三个区域镜像，供刻录 miniDVD 或
Wiikey Fusion / WODE 等其它设备使用；GCLoader 用全区的 `boot.iso` 即可。
详细说明见 [`gcloader/使用说明.md`](../gcloader/使用说明.md)。

自行重新打包（例如换了自己编译的 DOL）：

```bash
python tools/build_gcloader_iso.py --all
```

脚本复刻上游 Makefile 的 El Torito ISO 命令，自动修正 PowerPC 的 platform ID
与校验和，并做 20 项自检；所需头文件已附在 `tools/iso/`。
注意镜像里的启动文件必须是**自解压版** `swiss.dol`，绝不能用 `swiss-wiiload.dol`。

### 方式 D：按启动方式选专用文件

官方 Swiss 发布包按设备分目录，本包同样补齐了以下方式。**它们装的是同一份固件**，
只是包装格式不同，按自己设备挑一个即可：

| 设备 | 文件 | 放到哪 |
|---|---|---|
| Action Replay | `ActionReplay/AUTOEXEC.DOL` + `SDLOADER.BIN` | SD 卡根目录（两个都要） |
| FlippyDrive | 解压 `FlippyDrive/EXTRACT_TO_ROOT.zip` → `boot.dol` | SD 卡根目录 |
| Wiikey / WASP Fusion | `WiikeyFusion/swiss-zh.fzn` 等 | SD 卡根目录，按设备流程刷写 |
| Wii | 解压 `Wii/EXTRACT_TO_ROOT.zip` → `apps/swiss-gc/` | Wii SD 卡根目录，从 HBC 启动 |
| WODE | `WODE/swiss-zh(wode_extcfg).iso` | 按 extcfg 流程加载 |
| 记忆卡 | `MemoryCard/boot.gci` / `xeno.gci` | 用 GCMM 写入记忆卡 |

细节与刷写风险见 [`docs/启动方式文件说明.md`](../docs/启动方式文件说明.md)。
无论用哪种方式，游戏内复位所需的 `swiss/patches/apploader.img` 都要放在
**实际启动该游戏所用设备**的存储介质上。

### 黑屏排查

| 现象 | 原因 |
|---|---|
| 从加载器选文件后立刻黑屏 | 用了 `swiss-wiiload.dol`（原始构建），换成 `swiss.dol` |
| 卡在加载器菜单、选不动 | 文件名或分区问题，不是本包的事 |
| 进去后花屏 / 黑屏但网络有响应 | 视频模式问题，试试在另一台机器上改成 480i |

## 二、中文文件名

SD 卡上的文件可以直接用中文命名，例如：

```
/games/塞尔达传说.iso
/games/马力欧赛车.gcm
/apps/中文测试.dol
```

支持范围：**GB2312 全量 6763 字 ∪ Big5 常用区 5401 字** + 界面用字 + 中文译名表
+ 手工异体字 + ASCII 数字 + `□` 占位符，共 **8887 字**（r8 起）。两套字符集均 0 缺失，
所以简体中文文件名与常见繁体/日文游戏名（如「斑鳩」的「鳩」）都能正常显示。
GBK 扩展字、CJK 扩展区等仍不在库内，会显示 `□`。

含中文的字符串里，数字用 **r9 新绘的满格点阵**：14 行高、9 列宽、1px 笔画，
与汉字同高、同基线；纯英文/数字行仍用原版 IPL 字体。
r5~r8 用的是 Unifont 原字形（只有 10 行高 / 6 列宽），看起来比汉字小一圈，r9 已修正；
字距也从 10 调整到 12，数字与汉字中心对齐。

- `.dol` / `.iso` / `.gcm` 三种格式均已验证
- 2026-11-10 修复：旧版只收 GB2312 一级（3755 字），「噩」「飙」这类二级字会
  **静默留白**（看起来像文件名里少了一个字）。现已补齐二级字，并给字库外的新字
  加兜底：显示为空心方框 `□`，一眼能看出是字库没收录，而不是文件名有空格
- 2026-11-10 r8 扩库：又收到「斑鸠」的「鸠」不显示。**简体「鸠」U+9E20 在 r5~r7
  里本来就是好的**（从固件二进制逐字节复核过码位与位图），实际是日版原名「斑鳩」的
  「鳩」U+9CE9 不在 GB2312，或反馈者还在用 r1~r4 的 3771 字旧库。现由
  `--big5-common` 一次补齐 Big5 常用区 1885 个漏网繁体字，字库 7002 → 8887 字
- 2026-11-11 r9 修数字大小：中文串里的 `0-9` 从 Unifont 原字形（10 行高）换成
  `gen_font.py` 里 `fullsize_digit_bitmaps()` 重绘的 **14 行高 / 1px 笔画**满格点阵，
  与汉字同高同基线；`IPLFontWrite.c` 的 `ATLAS_DIGIT_XOFF` 4→0、
  `ATLAS_DIGIT_ADVANCE` 10→12 让中心对齐、字距不挤。没有用运行时 GX 缩放（会变形）
- GBK 扩展字、CJK 扩展区等仍不在库内，会显示 `□`；需要时把字加进
  `gen_font.py` 的 `EXTRA_VARIANTS` 或用 `--extra-chars` 传入，重新生成字库并编译
- 改数字字形请改 `gen_font.py` 的 `DIGIT_PATHS` / `DIGIT_SEG` 线段表，不要直接拉伸位图
- 已被 nkit 数据库识别的游戏显示的是**数据库里的游戏名**，不是文件名；
  只有未识别的文件（自制程序、未知镜像）才直接显示文件名。这是 Swiss 原有行为

## 四、已知限制

1. **设置项取值保留英文**：`On / Off / Yes / No / Standard / Fullwidth` 等。
   这些字符串同时用于 `swiss.ini` 的写入与解析，翻译会让旧配置全部读不出来、
   相关设置回落到默认值。已加自动化检查拦截这类改动。
2. **顶部标题栏保留英文**：`for GameCube` / `version 0.6` / `commit: … · revision: …`。
   这一行还要放 CPU 温度与右对齐的日期时间（日期串实测 277px），中文副标题更宽会直接
   压上去。温度按要求缩小到 0.45 后与其它元素共存，不再绘制在日期上方。
3. **设置页是半透明覆盖层**：会透出下层文件列表，标题栏会看到两层时间戳叠影。
   英文原版同样如此。
4. **GB2312 / Big5 常用区以外的字显示 `□`**：字库覆盖 GB2312 全量 6763 字
   ∪ Big5 常用区 5401 字 ∪ 界面/译名表用字，共 8887 字；GBK 扩展字、CJK 扩展区等
   仍不在库内，会显示 `□` 占位（不再静默留白）。
5. **硬件型号 / 协议名保留原文**：`IBM Gekko`、`SLOT-A`、`NTSC Revision 1.0`、FTP 指令等。
6. **设置页第 5、6 页按 Y 无帮助**：`tooltips_game[]` 用枚举值做下标初始化，但
   `get_tooltip()` 用页内序号索引，取到 NULL。原版即如此，与汉化无关。

## 五、自行构建

工具链：devkitPro + libogc2（MSYS2 环境）。

```bash
bash build-local.sh dev     # 全量构建
bash build-local.sh inc     # 增量构建（改一两个文件时，约 6 秒）
```

产物：`cube/swiss/swiss.dol`。

### 汉化维护流程

```bash
# 1. 改译文：编辑 translations/*.tsv（英文<TAB>中文，\n 表示换行）
# 2. 应用
python tools/apply_translations.py translations/settings.tsv
# 3. 预检（缺字 / 配置取值被翻译 / 字模不同步）
python tools/preflight.py
# 4. 构建并推送
bash build-local.sh inc && python tools/wiiload.py <IP> swiss.dol
```

### 工具一览

| 工具 | 用途 |
|---|---|
| `gen_font.py` | 由 `fonts/unifont.hex` 生成 `cjkfont.c/h`（16×16 点阵，r8 起分 18 页） |
| `check_glyphs.py` | 源码里用到的字符是否都在字模内（缺字会**整字不画**，不是豆腐块） |
| `check_config_arrays.py` | 拦截「翻译了 `swiss.ini` 取值」这类致命错误 |
| `preflight.py` | 上述检查串联，构建前必过 |
| `apply_translations.py` | 按映射表批量替换源码中的字符串 |
| `audit_widths.py` | 用实机导出的真实字宽，检查译文是否超出控件宽度 |
| `wiiload.py` | 推送 DOL 到实机（零依赖，替代 devkitPro 的 wiiload） |
| `grab_screen.py` / `pad.py` / `upload_file.py` | 抓图 / 远程按键 / 上传文件（需 DOL 内的诊断端点） |

字模参数：16×16 1bpp 位图，每页 512×256 I4（64KB），512 字/页；r8 起共 **18 页**，
运行时展开为 **1152KB** 图集，按字绑页。早期版本依次为 8 页 / 512KB、14 页 / 896KB。

> 移植到别处时用环境变量 `SWISS_GC_WORKSPACE` 指定工作区，或用 `SWISS_GC_GUI`
> 直接指定 `cube/swiss/source/gui` 目录；`audit_widths.py` / `make_release.py`
> 顶部的 `SRC` / `SWISS` 常量也需按实际路径调整。
